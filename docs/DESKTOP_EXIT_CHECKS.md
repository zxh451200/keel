# Windows 桌面退出手工验收清单

状态：未执行。此清单按生产源码整理，所有预期均须 Windows 真机确认，不能作为测试通过记录。
`AppLifecycleListener.onExitRequested` 仅处理 Flutter 框架收到的可取消平台退出请求；
普通窗口叉号 / Alt+F4 是否进入该链路是本次验收重点。强杀或不可取消退出不保障。
退出守卫无新依赖，未修改 native `SetQuitOnClose`。

## 准备与记录

可使用 Python 3.8+ 独立采集本次启动 PID、窗口 DPI/awareness/矩形与退出码：

```powershell
python scripts/desktop_probe.py <Release-exe-path> --output <new-report-directory> --prepare 30 --observe 20 --close
```

输出目录必须不存在；工具启动独立数据目录、清除继承的 FRB 测试 token，保留 stdout/stderr 和 `summary.json`。准备期间可手工制造草稿或移动到不同 DPI 的显示器。`--close` 仅发送一次普通 WM_CLOSE；不指定时只观察。超时保留存活进程和数据，不强杀、不自动删除证据。`OBSERVED_EXIT` 只是实际进程退出观察，不证明 Release 模式、Alt+F4、退出守卫、视觉布局或打印正确；这些验收仍按下面矩阵逐项执行。Linux 可运行 `python3 -B -m unittest discover -s scripts/tests -p 'test_desktop_probe.py'` 验证 mock 行为，不能替代 Windows API 实测。

## 场景与预期

| 待验收 | 操作 | 目标行为 |
|---|---|---|
| [ ] 无草稿 | 无脏输入时退出；分别覆盖无标签、仅只读标签、打开但未修改的用户编辑入口 | 无未保存确认，正常退出 |
| [ ] 隐藏 dirty 页 | 在新建用户工作区输入姓名/更改角色，切换到审计等其他标签，再退出 | 隐藏草稿仍触发确认；选继续编辑后窗口、标签和输入保留 |
| [ ] 弹窗 dirty | 从用户菜单打开新建用户弹窗，输入内容后退出 | canExit 检查弹窗草稿；选继续编辑后弹窗与输入保留，选放弃后才可继续退出检查 |
| [ ] 提交 busy | 分别在工作区、弹窗发起真实提交，在 busy 尚未结束时请求退出 | 本次退出被拒绝，不销毁编辑器、不重复提交；操作结束后可再次退出。未捕获 busy 窗口时记未覆盖，不记通过 |
| [ ] 诊断包 busy | 在诊断包准备、导出期间分别请求窗口退出及关闭诊断标签，重复发起退出 | busy 期间拒绝，不重复采集或写文件，弹窗与当前快照保留；成功或失败后忙碌状态释放，可再次退出。未捕获 busy 窗口时记未覆盖 |
| [ ] 备份操作 busy | 分别在创建、登记恢复、取消恢复请求未结束时关闭备份标签、关闭全部或退出；切换其他标签后重复 | busy 期间拒绝关闭备份页与退出，不重复请求；完成或失败后解锁，重读实际列表/待恢复状态。未捕获 busy 窗口时记未覆盖 |
| [ ] 恢复确认 | 打开恢复确认后请求窗口退出，再取消确认并重试；可受控时在确认期间切换用户 | 确认期间拒绝退出，无重复确认；取消后释放锁，身份改变后旧确认不提交 |
| [ ] 取消后重试 | 脏草稿退出确认中选继续编辑，再次请求退出并选放弃 | 第一次完整保留现场；第二次能再次确认并退出，无锁残留 |
| [ ] 多草稿全部允许 | 工作区与弹窗使用不同内容形成两份脏草稿，然后退出并依次放弃 | 先检查弹窗，再检查工作区；逐项确认，全部通过前不销毁页面 |
| [ ] 多草稿后项拒绝 | 同时保留上述两份草稿，弹窗草稿先选放弃，工作区草稿选继续编辑 | 取消整个退出；两份输入均保留，先前的确认不提前清空草稿；重试重新检查 |
| [ ] 重复退出 | 确认框打开期间重复点击窗口叉号或按 Alt+F4，再取消并重试 | 不叠加确认、不重复处理同一草稿；额外退出请求取消，首次取消后可重试 |
| [ ] 标签关闭在先 | 先用标签叉号/Ctrl+W/关闭全部触发草稿确认，确认未结束时请求窗口退出 | 共用锁阻止退出重入；无重叠确认，取消后页面和输入保留，后续退出可重试 |
| [ ] 窗口退出在先 | 退出确认期间尝试标签叉号、Ctrl+W、关闭其他/全部及表单取消入口（如可达） | 标签关闭不重入；同草稿 confirming 阻止重复确认；无提前销毁或重复提交 |
| [ ] 正常退出无残留 | 对无草稿及全部确认放弃的成功退出场景，在任务管理器核对本次应用 PID | 窗口关闭且对应应用进程消失，无 Keel 残留进程；记录观察时间与实际结果，调试工具进程单独辨认 |
