# ADR-007：日志与诊断脱敏

- 日期：2026-11-02
- 状态：沿用已选基线；部分实现已有源码，生成、运行与泄漏验收待完成。
- 范围：记录现有日志、错误和诊断安全边界；不记录本轮并行开发的审计 CSV 导出细节。

## 背景与依据

依据 `AGENTS.md` §3、§5.3、§6，以及 `docs/REQUIREMENTS.md` §1.4、§4、§9、§10.1。桌面故障需要可定位的关联 ID，同时不能把凭据、私人路径、完整连接串或业务记录带入提示、日志或分享材料。本地角色与 SQLite 审计不构成对本机管理员的安全隔离或防篡改承诺。

核对源码：`rust/src/api/error.rs`、`rust/src/diagnostics/{logging,events,redact,import_screen}.rs`、`rust/src/services/diagnostic_pack.rs`。这些是实现证据，不是测试通过证据。

## 已选设计与当前实现

1. Rust 使用 tracing、tracing-subscriber 与 tracing-appender。应用日志位于用户数据目录的 logs 下，按天滚动；初始化时尝试清理旧日志，保留数参数为 14，清理失败不阻止启动。它不是持续执行的严格磁盘配额。Release 默认 INFO，Debug 默认 DEBUG。
2. 错误按稳定 code 映射本地化用户提示，技术原因只进入诊断渠道，不靠解析 message 分支。当前 `ApiError::from` 在转换失败时生成关联 ID，返回 code、脱敏 message 和 ID，并记录日志及诊断事件；不能据此宣称所有跨层操作已具有完整链路追踪。
3. `redact` 集中处理密钥键值、Bearer、URL 用户凭据、邮箱和常见用户目录。文件 writer 写入前脱敏，事件缓冲写入时脱敏摘要，诊断包组合后再次脱敏全部文本。事件其他字段仍应由调用方提供安全的稳定标识，不能把任意输入放进 area、code 或关联 ID。
4. 最近事件只保存在本次进程内的 500 条缓冲中；诊断中心先按最低级别及关联 ID 精确过滤，再限量返回，不搜索历史日志文件。日志、诊断事件与业务审计各有用途，不能互相替代。
5. 诊断包默认只选择 runtime，recent_events 由用户显式选择；不读取原始日志、配置或数据库正文。Rust 准备完整脱敏快照，UI 预览并确认后按句柄导出同一快照，不重新采集。缓存最多 6 项、5 分钟、单份上限 1 MiB，绑定当前用户与角色；准备和导出均查权限，授权消费后失败也须重新准备。导出使用 create_new 避免覆盖，Unix 请求 0600；Windows 权限效果仍需验收。
6. 外部输入按不可信数据筛查：限制大小、UTF-8、JSON 结构和版本，提供有限长度脱敏预览；未知字段或未来版本不能成为配置导入候选。筛查本身不执行输入、不解压归档、不写正式配置。已编写的设置导入确认另在 Rust 权限和设置锁边界重新校验，只合并允许偏好；Windows COM/Linux GTK 系统配置文件选择已有源码，仅返回路径，仍待生成、编译及平台实测。完整外部诊断导入仍未完成。
7. 配置导入结果已有独立 `pending_settings_import_audit` 持久队列源码，成功事件与偏好同次保存，失败仅在本机配置健康、可写且有容量时入队，与变更队列合计最多 200 条，启动/后续保存幂等补写并确认入库后清理；不记录输入或路径，不提供配置/SQLite 跨存储事务。健康配置为记录失败可规范化/迁移 JSON，保留允许偏好语义与尚未确认入库的既有事件，不保证原始字节不变；坏/未来/不可写配置和补写后仍满的队列不得强行覆盖或挤出事件。详细边界见需求 §10.1，源码不代表运行验证通过。

## 替代方案与后果

| 方案 | 取舍与后果 |
|---|---|
| 只在 Flutter 展示时遮挡 | 原文仍可能落盘或跨桥接；采用 Rust 输出边界统一处理，并在导出时再次处理。 |
| 自动打包全部日志、配置和数据库 | 排障材料更多，但采集面和泄漏风险过大；采用最小类别采集与完整快照预览确认。 |
| 仅依靠规则，无需用户检查 | 规则会漏判或过度遮挡；保留用户检查步骤，无法可靠识别的内容默认不采集。 |
| 用普通日志代替审计 | 难以保留操作语义和结果；重要写入继续按既有 SQLite 审计设计处理，但不承诺本机防篡改。 |

统一规则减少多端差异，但调用方仍需避免采集敏感内容。双次脱敏不能恢复已被遮挡的信息，可能降低排障细节；有界缓冲会丢弃最旧事件，快照过期会增加重新预览步骤。

## 未验证、缺口与待外部决策

- 当前规则不能宣称覆盖需求 §4.2 全部类别：独立用户名、项目绝对路径、电话、客户/供应商/员工名及任意业务内容仍需补充领域规则和泄漏回归。
- panic 钩子向应用日志和事件缓冲写入脱敏信息后仍调用原钩子；控制台等其他输出通道不能据此视为已全面脱敏。异步日志在崩溃/强杀时的完整性也未获保证。
- 脱敏、缓存生命周期、权限、文件与 UI 回归已有测试源码；本次未运行。当前新增桥接仍待正式生成、依赖解析和 Windows 真实验证，阶段 0 的桥接成功不覆盖这些功能。
- 文件预检与打开之间的竞态、Windows ACL、原子文件行为、完整预览流程及分享前泄漏检查仍待验收。
- 二开业务的敏感字段目录、诊断材料的组织留存/分享规则需由业务及安全负责人明确；本 ADR 不新增上传服务、遥测或保密合规结论。
